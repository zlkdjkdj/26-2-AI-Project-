# PDF 요구사항 대응

루트의 기획 PDF와 촬영→안전 피드백→재촬영 흐름을 기준으로 웹 MVP를 확장했습니다.

| 기능 | 현재 구현 | 남은 범위 |
| --- | --- | --- |
| 공간·객체 분석 | YOLOv8n 일반 객체 + Grounding DINO 전선·콘센트·멀티탭, 작은 콘센트 확대 재검증 | 전용 공간 분류·더 다양한 라벨 데이터 |
| 맞춤 위험·DB | 5대상자·7공간, 1,293조건 규칙과 신생아·노약자 직접 확인 항목, 사진 관찰/사용자 확인 근거 구분 | 전문가 검증·실제 높이·동선·폭 측정 |
| 위험 위치 | 객체 박스, 주의·위험 색 표시 | 안전구역·정밀 영역 분할 |
| 인테리어 개선 | 컨셉 4개, 컬러 예시, 탐지 가구 가상 배치·저장, 모서리 몰딩 안내, 서버 사진 편집 API(비활성) | 치수 기반 배치 최적화·실제 사진 편집 활성화(유료 호출 금지) |
| 점수 | 25/12/5 감점과 80/60/40 상한, 구 기준 보존·재계산, 사진/현장 확인 점수 분리 | 점수의 실제 사고 위험과의 상관 검증 |
| 이력·비교 | 이력 검색, 대상자 필터, 사진 점수와 직접 점검 상태 비교 | 사진 정합·개별 객체 추적 |
| 생활 확인 | 동의 후 웹 활동·연결, 선택 위치, 야간 제외, 보호자 읽기 링크 | 모바일 백그라운드·휴대폰 전체 활동·문자/푸시 |

안전 분석에서 Gemini는 탐지/위험 DB의 설명만 담당하며 원본 사진과 좌표를 받지 않습니다. 별도의 인테리어 사진 편집 API는 명시적 동의 후 사진을 외부 Gemini에 전송하도록 구현했으나 유료 호출 금지 요청에 따라 비활성입니다. 실제 편집 이미지는 생성하지 않았습니다. 보이지 않는 조건과 안전구역을 만들어내지 않습니다. 일반 점검은 단일 사용자 로컬 MVP이므로 공개 서비스 전 인증·기록 격리·이미지 접근 제어가 필요합니다. 생활 확인 링크는 별도 역할 접근키를 사용합니다.
