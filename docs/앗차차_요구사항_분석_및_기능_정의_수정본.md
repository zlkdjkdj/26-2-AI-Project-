## 1. 프로젝트 개요

앗차차는 생활공간 사진에서 객체와 위치를 분석하고, 사용 대상자와 공간 유형에 맞는 위험 확인 항목 및 개선방법을 제공하는 생활안전 관리 서비스이다.

신생아, 영유아, 노약자, 휠체어 사용자, 거동 불편자를 주요 점검 대상으로 한다. 새로운 가구 구매보다 **현재 환경을 유지하면서 정리 → 재배치 → 안전용품 보완 → 필요한 경우 교체** 순서로 개선하는 것을 기본 방향으로 삼는다.

현재는 React 기반 웹에서 사진을 촬영하거나 업로드하면 FastAPI 서버가 실제 객체탐지 모델을 실행하고, 위험규칙 DB와 매칭하여 참고 안전점수와 개선 안내를 반환하는 MVP를 구현했다. 초기 Mock 방식은 개발·테스트 및 과거 시연 기록으로 구분하며, 실제 분석 실패 시 Mock 결과로 대체하지 않는다.

최종 결과물은 Android 스마트폰에 설치하여 사용할 수 있는 **APK 기반 앱**이다. 모바일 앱에서도 이미지 분석, 위험 판단, 점수 계산과 AI API 호출은 서버에서 수행하고, 앱은 촬영·전송·결과 확인을 담당한다.

생활 이상징후 기능은 현재 동의 기반 웹 활동·연결 확인 수준으로 구현했으며, 휴대폰 전체 활동 감지와 앱 종료 후 백그라운드 관찰은 향후 개발 범위이다.

## 2. 개발 배경 및 필요성

생활공간에는 낙상, 충돌, 감전, 추락, 화상, 질식 등 다양한 사고 위험이 존재한다. 같은 물건도 공간과 사용자 특성에 따라 확인해야 할 조건이 다르다.

예를 들어 전선은 노약자의 이동에 방해가 될 수 있으며, 영유아가 접근할 수 있는 콘센트는 보호 여부를 확인해야 한다. 신생아는 수면 공간의 부드러운 침구나 주변 끈을, 노약자는 침대 주변 조명과 이동 시 지지 수단을 함께 확인할 필요가 있다.

그러나 사진에서 물건이 보인다는 사실만으로 실제 통로 침범, 물기, 접근 높이, 전기 과부하 등을 확정할 수는 없다. 따라서 본 서비스는 **사진에서 관찰한 근거와 사용자가 직접 확인한 조건을 구분**하고, 확인되지 않은 조건을 안전하다고 판단하지 않도록 설계했다.

위험 판단의 목표 구조는 다음과 같다.

**객체 종류 + 이미지 내 위치 + 공간 유형 + 사용자 유형 + 직접 확인한 주변 조건 → 위험규칙 매칭 및 개선 안내**

실제 이동 동선 복원, 정확한 치수 측정과 사고 발생 확률 산출은 현재 구현 범위에 포함하지 않는다.

## 5. 핵심 기능

### 5.1 AI 기반 생활공간 이미지 분석

웹에서 촬영하거나 선택한 사진을 서버로 전송하면 다음 두 모델이 객체와 위치를 분석한다.

| 분석 모듈 | 현재 역할 |
| --- | --- |
| YOLOv8n / COCO 80종 | 의자·소파·테이블·침대·TV·가방·칼·가위 등 일반 객체의 위치 탐지 |
| Grounding DINO tiny / ONNX | 전선·콘센트·멀티탭을 별도로 탐지하여 일반 모델의 미지원 항목 보완 |

일반 객체 분석은 OpenCV DNN, 전기설비 분석은 ONNX 기반 CPU 추론으로 서버에서 실행한다. 사용자 기기에서 대형 모델을 실행하도록 구성하지 않는다.

전기설비는 종류별 탐지와 작은 콘센트 후보의 주변 확대 재검증을 적용한다. 겹치는 분류는 모델 출력에 따라 정리하고, 종류가 모호하면 직접 확인이 필요하다는 안내를 추가한다.

**처리 과정**

사진 입력 → 서버 이미지 검증·메타데이터 제거 → 실제 객체탐지 → 공간 선택·추정 확인 → 위험규칙 매칭 → 점수 계산 → 설명 생성 → 결과 표시

**출력 정보**

- 공간 유형과 추정 여부
- 탐지 객체 및 정규화된 위치 박스
- 사용자별 위험등급과 판단 근거
- 예상 사고와 정리·재배치·보완 방법
- 참고 안전점수 또는 점수 보류 안내

가구가 탐지되어도 날카로운 모서리가 확인되었다고 단정하지 않는다. 병을 자동으로 세제로 분류하지 않으며, 물기·실제 접근 높이·전기 과부하·통로 폭 등은 직접 점검으로 보완한다. 객체 존재 안내와 실제 위험 조건의 확인을 구분한다.

### 5.2 장소·사용자별 맞춤형 위험분석

**공간 유형:** 거실, 침실, 주방, 욕실, 현관, 복도, 계단  
**대상 유형:** 신생아, 영유아, 노약자, 휠체어 사용자, 거동 불편자

사용자는 공간을 직접 선택할 수 있다. 자동 확인은 변기, 냉장고·오븐, 침대, 소파·TV 등 탐지 객체에 근거한 **규칙 기반 공간 추정**이다. 전용 공간 분류 모델을 사용하거나 확정적인 공간 인식 정확도를 제공하는 기능은 아니다. 추정이 어려우면 직접 선택하도록 안내한다.

대표적인 점검 방향은 다음과 같다.

- 신생아: 수면 공간의 부드러운 침구, 침대 주변 끈, 끼임, 높은 기저귀 교환 위치 등 직접 확인
- 영유아: 콘센트 접근·보호 여부, 작은 물건, 계단 안전문 등 확인
- 노약자: 전선·장애물, 단차, 불안정한 의자, 침대 주변 조명·이동 지지 수단 등 확인
- 휠체어 사용자·거동 불편자: 장애물, 이동 공간과 옮겨 앉을 때 필요한 지지 환경 등 확인

사진으로 확정하기 어려운 조건은 **위험 있음 / 해당 조건 없음 / 미확인** 중에서 선택하고 메모를 저장할 수 있다.

### 5.3 위험요소 데이터베이스 기반 판단

현재 SQLite 서비스 DB에는 **1,293개의 대상·공간·객체·조건 조합 위험규칙**을 구성했다. 이 수치는 서로 다른 위험 종류나 모델 탐지 클래스가 1,293개라는 의미가 아니다.

규칙은 대상 유형, 공간 유형, 객체 유형, 조건, 예상 사고, 위험등급, 설명, 개선방법과 보완방법을 포함한다. 객체탐지 결과에서 제공하는 근거와 일치하는 규칙만 사진 위험 결과로 연결한다.

| 대상·공간 | 확인 조건 예시 | 예상 사고 | 안내 방향 |
| --- | --- | --- | --- |
| 노약자·거실 | 전선이 실제 이동 경로에 있는지 확인 | 걸림·낙상 | 벽면 방향 정리, 케이블 몰딩 보완 |
| 영유아·거실 | 접근 가능한 콘센트의 보호 여부 확인 | 감전 | 안전커버 등 보호 수단 확인 |
| 노약자·욕실 | 매트 고정 상태·물기 직접 확인 | 미끄러짐 | 물기 제거와 미끄럼방지 보완 |
| 신생아·침실 | 수면 공간의 부드러운 침구·주변 끈 확인 | 질식·끈 얽힘 | 위험 조건 정리 및 보호자 확인 |
| 노약자·침실 | 조명 접근성·이동 지지 부족 확인 | 낙상 | 조명·동선·지지 환경 보완 |

신생아·노약자 중심의 직접 확인 항목 12개를 추가했으며, CPSC·CDC 공개 자료 링크를 점검 항목에 연결했다. 위험규칙의 전문가 검증은 추가 과제로 남아 있다.

### 5.4 위험 위치 및 주의 표시

사진에서 탐지하고 위험규칙에 매칭한 객체의 위치를 Bounding Box로 표시한다. 주의·위험 위치 보기와 위험요소 선택을 통해 해당 위치의 상세 안내를 확인할 수 있다.

현재는 정밀 영역 분할이나 생활공간 전체의 동선 분석을 수행하지 않는다. **위험이 탐지되지 않은 영역을 안전구역으로 표시하지 않는다.** 실제 안전·주의·위험 영역을 공간 전체에 적용하는 기능은 향후 개발 범위이다.

### 5.5 개선방법 및 인테리어 가이드

개선 안내는 기존 물건을 활용하면서 최소한의 비용과 변경으로 안전성을 높이는 방향으로 제공한다.

1. 정리: 전선 정리, 바닥 물건 제거, 통로 확보
2. 재배치: 실제 통로와 고정 여부를 확인한 뒤 가구 위치 조정
3. 보완: 충격 흡수 모서리 몰딩·보호대, 콘센트 커버, 미끄럼방지 패드, 야간조명, 안전문, 손잡이 등
4. 교체: 정리·재배치·보완으로 해결하기 어렵거나 물건·시설 자체가 손상된 경우 검토

가구 모서리 보호 몰딩은 단단히 고정하고 작은 부품이 떨어지지 않도록 확인하는 내용으로 안내한다. 가구 모서리 보호와 아기 침대 범퍼는 구분하며, 아기 침대에 범퍼를 추가하도록 권장하지 않는다.

**인테리어 화면 흐름**

컨셉 선택 → 컨셉 컬러 예시 확인 → 탐지된 가구의 가상 배치 조절 → 컨셉·배치 저장

현재 선택 가능한 컨셉은 **미니멀 화이트, 내추럴 우드, 소프트 모던, 편안한 동선**의 4개이다. 가구 위치는 드래그 또는 좌표·회전 입력으로 조절할 수 있다. 배치도에서 가구끼리 겹치거나 경계를 벗어나는 경우 확인 안내를 표시한다.

초기 가구 위치와 도형 크기, 가운데 동선 선은 예시이다. 사진에서 평면도를 복원한 결과가 아니며, 방 치수 입력도 메모 용도이다. 실제 가구 치수·문 위치가 없어 통로 폭이나 휠체어 통과 가능성을 계산하지 않는다. 고정 가구나 벽걸이 TV는 임의로 옮기지 않도록 안내한다.

**실제 사진 AI 편집의 상태**

서버의 Gemini 이미지 편집 API 연결은 구현했다. 사진 전송 동의, 원본 일치 확인, 응답 검증과 오류 처리를 포함하지만, 사용자의 **유료 호출 금지 요청에 따라 비활성화**했다. 실제 편집 이미지는 생성하지 않았으며 현재 화면의 컬러 예시를 실제 사진 편집 결과로 표현하지 않는다.

컨셉 선택, 배치 저장, 개선 완료 체크 및 생성 이미지 자체는 안전점수를 올리는 근거로 사용하지 않는다.

### 5.6 참고 안전점수 및 개선 전후 비교

기존 점수가 과도하게 높게 표시되는 문제를 보완하여 현재 새 점검에는 다음 기준을 적용한다.

| 위험등급 | 감점 |
| --- | --- |
| 고위험 | 25점 |
| 중위험 | 12점 |
| 저위험 | 5점 |

기본 계산식은 다음과 같다.

**기본 점수 = max(0, 100 − 고위험 개수×25 − 중위험 개수×12 − 저위험 개수×5)**

추가 상한은 다음과 같다.

- 위험 항목이 존재하면 최대 80점
- 고위험 1개이면 최대 60점
- 고위험 2개 이상이면 최대 40점

예를 들어 고위험 1개와 중위험 1개가 있으면 기본 점수는 63점이지만 상한을 적용하여 60점이다. 중위험 1개만 있으면 기본 점수 88점에 상한을 적용하여 80점이다. 매칭한 사진 위험 항목이 없으면 100점으로 확정하지 않고 **점수 보류**를 표시한다.

점수는 현재 탐지 결과와 서비스 규칙에 한정한 **보수적인 참고값**이며, 실제 사고 발생 확률이나 공간의 안전 인증을 의미하지 않는다.

이전 점검 기록은 기존 기준인 15/7/3점 감점을 보존하고, 사용자가 최신 기준 적용을 선택하면 저장된 위험 항목으로 재계산한다. 사진을 새로 분석하지 않으며 이 작업만으로 새 위험 항목이 발견되지는 않는다. 서로 다른 점수 기준의 기록은 점수 차이를 비교하지 않는다.

사진 점수와 직접 점검을 반영한 종합 참고점수는 구분하여 제공하고, 같은 객체 그룹의 확인 항목이 중복 감점되지 않도록 처리한다. 개선 완료 체크만으로 점수를 변경하지 않는다.

재촬영 비교는 동일 대상·공간 조건에서 점수와 위험 종류·조건·개수 변화를 비교한다. 개별 물건을 추적하거나 개선 완료를 확정하는 기능은 아니므로 촬영 각도, 가림, 탐지 오차의 영향을 고려해야 한다.

### 5.7 생활 확인 및 보호자 안내

현재 구현한 기능은 **동의 기반 웹 생활 확인**이다.

- 해당 웹 화면의 클릭·키 입력으로 마지막 활동 시간을 기록한다.
- 약 1분 간격으로 서버 연결을 확인한다.
- 설정한 미활동 기준과 확인 시간대를 적용한다.
- 3분 이상 연결 기록이 없으면 연결 확인 필요 상태와 장시간 웹 미활동 상태를 구분한다.
- 같은 상태의 확인 안내를 중복 생성하지 않도록 관리한다.
- 별도의 보호자 읽기 링크를 제공한다.

위치 기록은 선택 동의 및 브라우저 권한이 있는 경우 **화면이 열려 있고 표시되는 동안 약 1시간 간격으로 시도**한다. 브라우저 종료·절전·백그라운드 제한에 따라 기록이 중단될 수 있으며 정시 전송을 보장하지 않는다. 마지막 위치는 보호자 화면이나 설명 AI에 제공하지 않고, 생활 확인을 중지하면 제거한다.

현재 이상 안내는 연결·웹 활동 시간 기준이다. 위치 변화나 과거 생활 패턴을 학습하여 사고를 판단하는 기능은 구현하지 않았다. 보호자는 확인 화면에서 안내를 볼 수 있으나 **문자·푸시 알림, 휴대폰 전체 사용정보 수집, 앱 종료 후 지속 관찰은 미구현**이다.

실제 사진 편집은 별도의 외부 사진 전송 기능이므로 설명 생성과 구분하며, 현재 호출을 차단한 상태이다. 재점검 비교와 생활 확인 안내는 현재 규칙·정형 문구 중심으로 처리하며, 해당 문구가 모두 생성형 AI로 작성되는 것은 아니다.

## 10. 프로젝트 차별점 및 최종 방향

앗차차는 **실제 객체탐지 + 대상·공간별 위험규칙 + 직접 점검 + 개선 안내 + 재점검 기록**을 연결한 서비스이다.

핵심 차별점은 현재 가구와 공간을 최대한 유지하면서 정리, 재배치와 안전용품 보완을 먼저 제안한다는 점이다. 사진 분석만으로 확인할 수 없는 조건은 직접 점검으로 보완하고, 모델이 탐지하지 못한 영역을 안전하다고 표시하지 않는다.

인테리어 컨셉과 가상 배치는 개선 방향을 검토하기 위한 도구로 제공하며, 실제 개선 완료와 점수 계산은 분리한다. 생활 확인 역시 사고 판정이 아닌 직접 확인을 돕는 보조 기능으로 한정한다.

최종 목표는 서버 기반 분석을 재사용하는 Android APK를 완성하고, 실제 기기에서 촬영부터 피드백·개선·재점검까지 이어지는 서비스 흐름을 제공하는 것이다.

## 11. 시스템 구조 및 개발 환경

### 11.1 현재 개발 기술

| 구분 | 현재 사용 기술 | 역할 |
| --- | --- | --- |
| 웹 프론트엔드 | React, Vite | 사진 입력·분석 결과·가이드·기록 화면 |
| 백엔드 | Python, FastAPI, Uvicorn | 이미지 검증·분석·위험 판단·점수·API |
| 일반 객체탐지 | YOLOv8n ONNX, OpenCV DNN | 일반 객체와 위치 탐지 |
| 전기설비 탐지 | Grounding DINO tiny ONNX | 전선·콘센트·멀티탭 탐지 |
| 위험 설명 | Gemini API, 설정 모델 gemini-3.1-flash-lite | DB 결과 기반 설명 생성 |
| 서비스 DB | SQLite | 점검·위험규칙·직접 점검·배치·생활 확인 저장 |
| 참고자료 DB | 별도 SQLite 카탈로그 | 공개 이미지 출처·라벨·해시 관리 |
| 이미지 보관 | 개발 서버 로컬 파일, 저장 선택 | 원본 사진은 기본적으로 미보관 |
| 모바일 앱 | React Native·Expo 도입 계획 | APK 촬영·전송·결과 UI, 아직 프로젝트 미생성 |

PostgreSQL·Supabase·AWS·Oracle DB는 현재 사용 기술이 아니다. 운영 단계에서는 HTTPS 서버, 인증과 사용자별 데이터 접근 제어를 먼저 마련하고, 동시 사용량·관리 요구에 따라 DB나 저장소를 선택한다. 특정 클라우드나 Oracle DB 사용을 필수 조건으로 두지 않는다.

현재 폴더에는 Git 저장소가 구성되어 있지 않으므로 Git·GitHub 관리도 향후 작업으로 구분한다.

### 11.2 현재 시스템 구조

```text
React 웹: 촬영·사진 선택·대상/공간 선택
                   ↓ REST API
FastAPI 서버: 입력 검증·이미지 처리
                   ↓
YOLO + Grounding DINO 객체탐지
                   ↓
SQLite 위험규칙 매칭 + 참고점수 계산
                   ↓
Gemini 설명 API 또는 DB 안내 문구
                   ↓
결과 JSON → 웹의 위치 표시·피드백·가이드·기록
```

백엔드는 개발 PC에서 실행한다. 이는 운영 서버 배포 완료 상태가 아니며, 모바일 기기에서 사용할 때에는 접근 가능한 서버 주소와 네트워크 환경이 필요하다.

### 11.3 향후 모바일 구조

```text
Android 앱: React Native + Expo 개발 계획
      촬영·갤러리 선택·사진 전송
                   ↓ HTTPS API
          기존 FastAPI 분석 서버
                   ↓
       객체탐지·위험 DB·점수·설명
                   ↓
        앱의 위험 위치·피드백 표시
                   ↓
          개선·재점검·기록 확인
```

Expo Go는 모바일 개발·테스트 계획의 일부이며 최종 설치용 APK와 동일하지 않다. 백그라운드 위치·네이티브 권한 기능은 별도 개발 빌드 및 Android 기능 구현 범위를 검토해야 한다. 현재 모바일 프로젝트와 APK는 생성하지 않았다.

### 11.4 주요 데이터 모델 및 API

서비스 DB는 사용자·대상자·공간·점검·위험·개선 추천·위험규칙 외에 직접 점검, 가이드 완료 상태, 인테리어 계획, 생활 확인 세션과 안내를 저장한다. 사용자 테이블이 존재하더라도 회원가입·로그인 인증이 구현된 것은 아니다.

| 주요 API | 역할 |
| --- | --- |
| POST /api/analyze/image | 실제 사진 분석 및 결과 저장 |
| GET /api/scans, /api/scans/{id} | 점검 이력·상세 결과 조회 |
| POST /api/scans/{id}/compare | 같은 조건의 재점검 비교 |
| POST /api/scans/{id}/rescore | 저장된 위험을 최신 점수 기준으로 재계산 |
| PATCH /api/scans/{id}/field-checks | 직접 확인 상태·메모 저장 |
| PATCH /api/scans/{id}/guide-tasks | 가이드 완료 상태 저장 |
| GET, PATCH /api/scans/{id}/interior | 컨셉·배치 조회 및 저장 |
| POST /api/scans/{id}/interior/preview | 실제 사진 편집, 현재 비활성 |
| GET /api/scans/{id}/report | HTML·JSON 점검 보고서 제공 |
| /api/care/* | 동의·활동·연결·보호자 조회·중지 |

환경변수는 백엔드 `.env`에서 관리하고 `.env.example`로 설정 항목을 안내한다. API 키를 앱·웹 코드에 포함하지 않는다.

## 12. UI/UX 개발 방향

화면은 기능을 한 번에 나열하기보다 **사진 촬영 → 안전 피드백 → 정리 후 재점검**을 중심으로 구성했다. 밝은 배경, 여백, 단순한 카드와 버튼을 사용하는 모바일 중심 웹 화면이다.

### 현재 웹 화면

- 사진 촬영 또는 기존 사진 선택
- 대상 유형 및 공간 선택
- 분석 요청과 진행·오류 안내
- 위험 위치와 항목별 개선 피드백
- 참고점수와 점수 보류·기준 안내
- 인테리어 컨셉·가상 배치·안전 개선 체크리스트
- 직접 점검과 메모
- 점검 이력 검색·재점검·보고서
- 선택적인 웹 생활 확인 및 보호자 조회

### 향후 모바일 화면

기존 API를 재사용하여 촬영·갤러리·위험 박스 표시·재점검 흐름을 실제 Android 기기에 맞게 구현한다. API 통신 실패, 권한 거절과 사진 업로드 오류를 화면에서 처리하고, APK 설치·실기기 시연을 최종 확인 기준으로 삼는다.

## 13. 검증 결과와 남은 개발 과제

### 13.1 기존 검증 결과

다음은 **2026년 10월 1일 검증 기록**이며, 문서 수정일에 새로 실행한 성능 평가 결과는 아니다.

- 실제 YOLO·Grounding DINO 추론을 포함한 당시 백엔드 검사 69개 통과
- 이후 점수·직접 점검·인테리어 변경을 포함한 빠른 검사 77개 통과, 무거운 전기설비 이미지 추론 회귀 2개 제외
- 마지막 사진 편집 API 변경 이후 모의 호출 검사 2개 추가 통과
- 프론트엔드 배포용 빌드 통과
- 390px 모바일 화면 확인 및 컨셉·배치의 서버 재시작 후 유지 확인
- 사용자 거실 사진에서 전선 1개·콘센트 2개 탐지, 멀티탭 오분류 없음 확인
- 공개 멀티탭 사진과 빈 단색 사진 회귀 검증
- 실제 설명 API 연동과 오류 처리 확인, 사진 편집은 모의 HTTP로만 검증

소수 사진의 성공 결과나 테스트 통과 수를 일반 탐지 정확도로 해석하지 않는다. 기록상 전기설비 분석 단계는 테스트 CPU에서 사진당 약 16~25초였으며, 설명 API와 요청 대기에 따라 전체 시간이 달라질 수 있다.

### 13.2 남은 과제

- 다양한 양성·음성·가림·작은 객체 사진으로 종류별 precision/recall 및 위치 정확도 평가
- 위험규칙·점수 기준의 전문가 검토
- React Native·Expo 모바일 프로젝트와 APK 제작
- 실기기 카메라·갤러리·서버 연결·재점검 검증
- 운영 HTTPS 서버, 인증·사용자별 기록 격리·사진 접근 제어
- Git·GitHub를 통한 버전 관리
- 백그라운드 위치·푸시·휴대폰 활동정보 기능의 권한·지원 범위 검토
- 실측 기반 배치·공간 분석 및 실제 사진 편집 활성화 여부 검토
