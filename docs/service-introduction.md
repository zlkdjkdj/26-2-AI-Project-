# 앗차차 서비스 소개 및 기술 설명

## 1. 서비스 소개

**앗차차는 사진으로 생활 공간의 위험 후보를 살펴보고, 사용하지 않는 Android 휴대폰을 홈캠으로 활용하는 생활안전 앱입니다.** 가구와 전기설비 주변에서 확인이 필요한 곳을 사진 위에 표시하고, 사용자가 살펴볼 사항과 개선 권고를 제공합니다. 다른 휴대폰에서는 촬영 기기의 영상을 실시간으로 볼 수 있습니다.

가정은 익숙한 공간이지만 통로의 전선이나 가구 주변은 놓치기 쉽습니다. 별도의 카메라를 구매하거나 복잡한 서버를 운영하기 어려운 상황도 있습니다. 앗차차는 스마트폰을 활용해 이러한 확인 과정을 돕고자 합니다. 가족의 공간을 살펴보는 보호자와 집 안 환경을 점검하려는 사용자를 주요 대상으로 합니다.

두 기능은 목적과 작동 방식이 다릅니다. **사진 점검은 정지 이미지에서 위험 후보와 권고를 제공하고, 홈캠은 기기 간 영상을 보여줍니다.** 사진에서 찾은 위험 요소가 홈캠 영상에서 실시간으로 탐지되는 것은 아닙니다.

## 2. 사용자 경험

### 사진 안전점검

1. 앱에서 사진 안전점검을 열고 필요한 모델을 내려받습니다. 기본 가구 모델은 약 45MB이며, 전선·플러그 등 추가 후보와 일부 가구 분류를 확인하는 모델은 약 204MB입니다.
2. 공간을 촬영하거나 기존 사진을 선택합니다. 가구와 바닥, 주변 통로가 함께 보이면 결과를 살펴보기 쉽습니다.
3. 앱은 휴대폰 안에서 객체 후보를 찾고, 위치와 종류에 맞는 점검 항목을 생성합니다. 추가 모델 사용 시 1차 결과가 먼저 보이고 최종 결과에서 항목과 점수가 달라질 수 있습니다.
4. 사용자는 사진을 확대하거나 번호를 선택해 해당 박스만 확인하고, 종합 피드백과 개선 권고를 읽습니다.

탐지 박스는 실제 물체나 위험 상태를 확정하는 표시가 아닙니다. 예를 들어 가구 모서리는 가구가 탐지된 위치에서 단단한 모서리가 노출돼 있는지 확인하도록 안내하며, 모서리의 날카로움을 직접 측정하지 않습니다. 물기와 미끄러움, 물건의 실제 높이와 안정성, 전기설비의 손상도 사진만으로 확정할 수 없습니다.

### 공기계 홈캠

1. 촬영용과 모니터링용 Android 휴대폰에 앱과 Tailscale을 설치하고 같은 Tailnet에 연결합니다.
2. 촬영 기기에서 일회용 등록 QR을 만들고 모니터링 기기에서 스캔합니다.
3. 촬영을 시작하면 모니터링 기기에서 WebRTC 영상을 확인할 수 있습니다. 두 기기는 서로 다른 인터넷 회선을 사용할 수 있습니다.
4. 화면 확대·회전, 카메라 전환, 사람 위치 표시와 수동 녹화 등 제공된 기능을 사용할 수 있습니다. PIP와 영상 저장은 기기별 검수가 필요합니다.

촬영 기기는 충전 상태에서 앱과 화면을 켜 두는 것을 전제로 합니다. 화면 잠금이나 백그라운드 촬영은 지원하지 않습니다. 실험적 낙상 의심 기록은 촬영 기기에서 직접 켜야 하며, 자세 변화 규칙으로 전후 영상 저장을 시도합니다. 긴급 신고나 푸시 알림은 제공하지 않습니다.

Expo Go에는 필요한 WebRTC와 ONNX 네이티브 모듈이 없으므로 자체 Android 빌드를 사용합니다. 모델 가중치는 저장소에 포함하지 않고 앱에서 내려받으며 SHA-256을 확인합니다. 별도의 PC 분석 서버나 Gemini API는 현재 사진 분석 경로에 사용하지 않습니다.

## 4. 사진 분석 구현 방식

### 입력부터 결과까지

```text
사진 촬영·선택
    ↓
기기에서 이미지 전처리
    ├─ YOLOv8s: 일반 물체·가구 후보
    └─ 선택형 Grounding DINO: 전기설비·바닥·일부 가구 후보
    ↓
박스 중복 정리 및 일부 가구의 분류 충돌 확인
    ↓
물건 종류·사진상 위치에 규칙 적용
    ↓
항목별 확인 안내 + 참고 점수 + 종합 피드백
```

YOLOv8s는 사전 학습된 범주에 속하는 물체를 찾습니다. 기본 모델에 없는 선풍기와 세부 구분이 필요한 의자·책상·테이블은 선택형 Grounding DINO에서 각각 추가 질의합니다. 전선, 멀티탭, 플러그, 물기 및 러그 등도 선택형 모델에서 후보로 살핍니다. 이름이 같거나 겹치는 후보는 박스의 겹침 정도를 바탕으로 정리합니다.

두 모델이 같은 위치의 가구를 다르게 분류할 때는 결과를 무조건 확정하지 않고 **물건 종류 확인 필요**로 표시합니다. 이 불확실 항목은 참고 점수에 포함하지 않습니다. 모델별 신뢰도는 서로 직접 비교해 정답 확률처럼 해석하지 않습니다.

### 위험 후보와 참고 점수

앱은 탐지된 물건의 종류와 사진 좌표를 기존 규칙에 대입해 권고를 만듭니다. 예를 들어 가구라면 모서리 노출과 이동 동선을 살피도록 안내하고, 바닥의 전선 후보라면 실제 통로를 가로지르는지 확인하도록 안내합니다. 화면 위쪽의 작은 물건은 실제로 높은 곳이나 가장자리에 있는지 확인하는 후보로 취급합니다.

현재 점수는 100점에서 고위험 항목당 25점, 중위험 12점, 저위험 5점을 차감하는 규칙을 사용합니다. 고위험 항목이 1개면 상한 60점, 2개 이상이면 상한 40점이며, 고위험 항목이 없을 때는 상한 80점입니다. 점수에 반영할 항목이 없으면 점수를 산정하지 않습니다. **이 수치는 사고 확률이나 안전 인증이 아니라 확인 항목에 한정된 참고값**입니다. 탐지하지 못한 위험은 반영되지 않습니다.

### 속도와 정확도 접근

기본 결과를 먼저 표시하고 선택 모델 결과가 끝나면 갱신합니다. 기기의 메모리·CPU 조건이 충분할 때 모델과 일부 질의를 병렬로 실행하고 입력 텐서를 재사용하며, 조건이 부족하면 순차 실행합니다. 추가 모델 실패 시 기본 결과를 유지하고 추가 분석 실패를 알립니다.

이는 모델을 추가하면서 대기 체감을 줄이기 위한 설계입니다. 기기 성능, 메모리와 사진에 따라 전체 시간은 달라집니다. 현재 S25에서의 정확도와 총 소요 시간 개선은 아직 실측 결과가 필요하며, 모델 추가가 모든 상황에서 정확도나 속도를 높인다고 보장하지 않습니다.

### AI 탐지 기준: 입력, 문턱값, 박스 정리

아래 수치는 현재 코드의 **후보 선별 설정**으로, 실험과 검증에 따라 바뀔 수 있습니다. 신뢰도 문턱값은 모델 출력이 후보로 표시될 만큼 높은지 가르는 기준이지, 물건이 맞을 확률이나 사고 확률을 보증하지 않습니다. 두 모델의 출력 점수도 서로 같은 척도로 보정되어 있지 않습니다.

| 단계 | 현재 처리 기준 | 의미와 한계 |
| --- | --- | --- |
| YOLO 입력 | 사진 비율을 유지해 640×640 입력에 맞추고 남는 부분을 채움 | 원본을 축소하면 멀리 있거나 얇은 물체가 작아질 수 있음 |
| YOLO 후보 | 80개 클래스의 출력 중 가장 높은 점수를 선택. 테이블은 0.24 이상, 나머지는 0.35 이상 | 기본 모델은 일반 물체 중심이며 전선·플러그 전용 모델이 아님 |
| 가구 추가 확인 | 화면 아래에 충분히 큰 테이블 후보가 없으면 사진의 하단 좌·우 겹침 영역을 다시 분석 | 이 추가 분석에서는 의자·소파·침대·테이블 후보를 살핌. 여러 번 분석하므로 시간이 늘 수 있음 |
| 추가 모델 입력 | 전체 사진과 하단 좌·우 잘라낸 영역을 800×800으로 준비 | 잘라낸 영역의 전선 후보를 원본 좌표로 되돌려 합침. 전체 사진 비율은 입력 크기에 맞춰 조정됨 |
| 전기설비 후보 | 전선·콘센트·멀티탭·플러그 질의별 점수 0.35 이상 | 각 질의의 후보이며 겉모습이 비슷하면 종류가 섞일 수 있음 |
| 바닥 후보 | 물기와 러그·매트 질의 점수 0.48 이상 | 반사나 바닥 무늬도 후보가 될 수 있고 마찰력을 측정하지는 못함 |
| 추가 가구 후보 | 선풍기 0.50, 의자 0.38, 책상과 테이블 각각 0.50 이상 | 개별 텍스트 질의 결과를 사용하며 범주가 겹치거나 누락될 수 있음 |
| 중복 정리 | 같은 종류의 박스가 많이 겹치면 IoU 0.45 초과를 기준으로 정리 | IoU는 두 박스의 교집합 넓이를 합집합 넓이로 나눈 값. 서로 다른 대상이 붙어 있으면 구분이 어려울 수 있음 |
| 두 모델의 가구 비교 | 박스가 충분히 겹치면 동일 위치 후보로 연결하고, 분류가 충돌하면 확인 필요로 표시 | 테이블과 책상 조합에는 별도 처리 규칙이 있음. 충돌이 없다고 정답이 증명되는 것은 아님 |

전선은 전체 사진 외에 사진 하단의 좌·우 겹침 영역에서도 확인합니다. 바닥 가까이에 있는 작은 선을 보완하기 위한 방식이지만, 창문 주변처럼 얇고 배경과 섞이는 전선은 여전히 놓칠 수 있습니다. 선택형 모델은 전체 메모리가 약 5GiB 미만인 기기에서는 제한됩니다.

### 탐지 결과에서 실제 피드백까지

AI가 반환하는 것은 주로 **물체 종류, 모델 점수, 사진에서의 박스 좌표**입니다. 위험 여부와 권고는 별도 규칙에서 만듭니다.

1. **물체 후보 정리:** 탐지 점수와 박스 겹침을 기준으로 중복을 정리합니다. 전기설비 후보가 서로 겹치면 유사한 종류를 함께 안내할 수 있습니다.
2. **사진 내 위치 확인:** 박스가 사진의 아래쪽·가운데에 있는지, 물건이 사진 위쪽에 보이는지 등을 확인합니다. 예를 들어 사진 아래쪽은 실제 바닥이나 통로일 가능성을 살펴보는 단서일 뿐, 실제 거리나 높이를 측정한 값은 아닙니다.
3. **규칙 적용:** 가구는 모서리와 동선을, 전선 후보는 걸림 가능성을, 플러그는 연결·손상·물기 여부를, 매트·물기 후보는 미끄러짐 여부를 확인하도록 안내합니다. 사진 위쪽의 일부 물건은 실제로 높은 곳이나 가장자리에 있는지 확인하도록 합니다.
4. **확인 항목과 우선순위 생성:** 해당 규칙에 정의된 위험 등급·설명·권고를 사용합니다. 가구의 모서리 박스를 별도로 분할하거나 전선의 통전 상태를 분석하지는 않습니다.
5. **종합 피드백:** 반환된 항목을 위험도 순으로 정리하고 고·중·저 위험 개수와 종류 확인 필요 개수를 표시합니다. 중복 권고를 걸러 최대 세 가지 행동을 요약합니다.
6. **점수 산정:** 종류 확인 필요 항목은 점수에서 빼고 나머지 항목에 차감·상한 규칙을 적용합니다. 점수화할 항목이 없으면 산정을 보류합니다.

예를 들어 사진 아래쪽의 전선 후보가 검출되면 앱은 해당 박스와 함께 이동 경로에 놓였는지, 선을 정리할 필요가 있는지 확인하도록 안내합니다. 이는 **모델이 전선이라고 판단한 후보와 사진상 위치를 근거로 생성한 권고**이며, 실제 전선 여부나 사람이 걸려 넘어질 상황을 확정한 것은 아닙니다.

### 점수 계산 예시

- 저위험 항목만 2개면 원래 계산값은 `100 - 5 - 5 = 90`이지만 고위험이 없는 경우의 상한 80점을 적용해 **80점**입니다.
- 고위험 1개와 중위험 1개면 `100 - 25 - 12 = 63`에 고위험 1개 상한을 적용해 **60점**입니다.
- 종류 확인 필요 항목만 있으면 차감 대상으로 확정하지 않아 **점수 산정 보류**입니다.

이 규칙은 현재 구현 설명이며, 의학적·통계적으로 검증된 안전 지수가 아닙니다. 같은 사진이라도 후보가 빠지거나 오인식되면 점수가 달라질 수 있습니다.

## 5. 홈캠 구현 방식과 보안

```text
촬영용 Android                           모니터링용 Android
QR 생성 ─────────── 1회 등록 ──────────→ QR 스캔
카메라 → WebRTC 영상 ═ Tailscale 경로 ═→ 영상 표시
   └─ 선택: 자세 변화 기록                  └─ 사람 위치 표시·수동 녹화
```

촬영 기기에 연결 정보 교환 기능이 있어 별도 PC 서버 없이 두 기기가 WebRTC 연결을 협상합니다. 영상 후보 경로는 Tailnet으로 제한하며 공개 STUN/TURN 서버를 필수 구성으로 두지 않습니다. 등록 정보는 보안 저장소를 사용합니다. Tailscale과 WebRTC의 암호화 통신을 활용하지만, Tailnet의 기기 권한과 사용자 계정, 휴대폰 자체의 보안 설정도 함께 관리해야 합니다.

두 휴대폰이 같은 물리적 Wi-Fi에 있을 필요는 없습니다. 다만 각각 인터넷에 연결되어 같은 Tailnet에 접근할 수 있어야 하며, 네트워크 환경에 따라 지연이나 연결 실패가 발생할 수 있습니다. 사진 모델 다운로드에는 인터넷이 필요하지만 다운로드와 검증 후 사진 추론 자체는 오프라인으로 실행됩니다.

모니터링 화면의 사람 표시는 ML Kit 자세 인식 결과를 이용해 최대 한 명을 표시하며 신원 확인 기능이 아닙니다. 실험적 낙상 의심 기능 역시 어깨·엉덩이 위치와 시간에 따른 변화에 적용한 규칙으로, 검증된 낙상 판별 모델이 아닙니다. 녹화는 기기 내에 저장되며, 수동 녹화는 최대 60초의 무음·저해상도 방식입니다. Android 10 이상 갤러리 복사, PIP, 저장·재생 및 자세 변화 기록은 기기별 검수가 필요합니다.

## 6. 예상 기술 질문과 답변

**Q. AI가 사진과 권고를 모두 생성하나요?**  
A. 객체 후보와 위치는 기기 내 YOLOv8s 및 선택형 Grounding DINO가 추론합니다. 위험 항목, 문구, 참고 점수와 종합 피드백은 탐지 결과에 적용한 앱의 규칙으로 만듭니다. 생성형 AI가 사진을 해석해 답변을 작성하는 구조는 아닙니다.

**Q. Gemini API 또는 PC 서버가 필요한가요?**  
A. 현재 사진 점검과 휴대폰 간 홈캠 동작에 둘 다 필요하지 않습니다. 단, 모델 최초 다운로드와 원격 홈캠의 Tailscale 연결에는 인터넷이 필요합니다.

**Q. 왜 두 사진 탐지 모델을 사용하나요?**  
A. 기본 객체 탐지 모델이 제공하는 범주만으로는 전선·플러그와 같은 세부 대상을 다루기 어렵기 때문입니다. 선택형 모델이 특정 후보를 추가 확인합니다. 두 모델이 불일치하면 확인 필요로 표시하지만, 조합 자체가 정확도를 보장하지는 않습니다.

**Q. 선풍기가 의자로 나오면 어떻게 처리하나요?**  
A. 추가 모델이 같은 위치에서 다른 가구 후보를 발견하면 겹침을 확인해 불확실 항목으로 표시합니다. 어느 모델도 놓치거나 두 모델이 같은 오분류를 할 수 있으므로 실제 사진과 대조해야 합니다.

**Q. 가구의 날카로운 모서리나 전선 손상을 직접 판단하나요?**  
A. 아닙니다. 사진에서 탐지된 가구 또는 전기설비를 바탕으로 현장에서 확인해야 할 항목을 제시합니다. 날카로움, 통전, 손상, 발열 등의 실제 상태는 확인할 수 없습니다.

**Q. 안전점수 80점은 집이 80% 안전하다는 뜻인가요?**  
A. 아닙니다. 탐지되어 점수화 가능한 확인 항목에 적용한 규칙 기반 참고값입니다. 미탐지 위험은 계산되지 않으며 사고 확률이나 인증을 의미하지 않습니다.

**Q. 기기가 다른 네트워크에 있어도 연결되나요?**  
A. 두 기기가 인터넷과 같은 Tailnet에 연결되어 통신할 수 있으면 서로 다른 Wi-Fi나 모바일 데이터를 사용할 수 있습니다. 동일한 물리적 네트워크는 필수가 아닙니다.

**Q. Tailscale만 켜면 누구나 영상을 볼 수 있나요?**  
A. 앱은 Tailnet 경로에 더해 일회용 QR 기반 기기 등록을 사용합니다. 다만 접근 통제의 효과는 Tailnet 설정과 기기·계정 관리에도 의존하므로 QR과 기기 등록 정보를 타인에게 노출하지 않아야 합니다.

**Q. 영상의 사람을 인식하면 낙상도 정확히 판단하나요?**  
A. 아닙니다. 모니터링의 사람 위치 표시와 촬영 기기의 실험적 자세 변화 기록은 별개입니다. 후자는 낙상으로 의심되는 변화에 대한 저장 시도일 뿐이며 오탐·누락이 가능합니다.

**Q. 클라우드 AI를 쓰지 않는 이유는 무엇인가요?**  
A. 사진을 외부 분석 서버에 보내지 않고 모델 설치 후 오프라인으로 분석하기 위한 선택입니다. 대신 휴대폰 성능과 저장 공간의 제약을 받으며, 모델 다운로드가 필요합니다.

**Q. 속도와 정확도는 어떻게 검증하나요?**  
A. 같은 사진 모음과 같은 기기에서 정답 라벨을 기준으로 클래스별 탐지 성능과 오탐·누락을 비교하고, 모델 로딩을 포함한 총 소요 시간 및 반복 실행 시 발열·메모리를 측정해야 합니다. 현재 단위 테스트와 일부 사례 확인만으로 일반적인 정확도나 S25 속도 향상을 수치로 주장하지 않습니다.

**Q. APK를 바로 상용 배포할 수 있나요?**  
A. 실기기 기능·성능 검수와 보안 점검이 추가로 필요합니다. 특히 모델과 라이브러리의 사용·재배포 조건을 확인해야 하며, 현재 YOLOv8s 가중치에는 AGPL-3.0 라이선스가 명시되어 있습니다.

### AI 모델과 정확도에 관한 질문

**Q. 객체 탐지와 이미지 분류는 어떻게 다른가요?**  
A. 이미지 분류는 이미지 전체의 대표 범주를 예측하고, 객체 탐지는 여러 물체의 종류와 위치 박스를 함께 예측합니다. 이 앱은 위치별 안내를 위해 객체 탐지 결과를 사용합니다.

**Q. 모델의 신뢰도 0.5는 정답일 확률이 50%라는 뜻인가요?**  
A. 그렇게 단정할 수 없습니다. 현재 값은 모델 출력에 적용하는 후보 선별 점수입니다. 실제 정답 비율을 뜻하려면 별도 데이터셋을 사용한 보정과 검증이 필요합니다.

**Q. 문턱값을 낮추면 정확해지지 않나요?**  
A. 놓치는 후보를 더 찾을 가능성이 있지만 잘못된 후보도 늘 수 있습니다. 문턱값을 높이면 반대로 오탐이 줄 수 있으나 실제 물체를 놓칠 수 있습니다. 사진별 정답 데이터로 정밀도와 재현율을 함께 측정해야 합니다.

**Q. 정밀도와 재현율은 각각 무엇인가요?**  
A. 정밀도는 탐지했다고 표시한 항목 중 실제 정답인 비율이고, 재현율은 실제 정답 중 찾아낸 비율입니다. 가정 안전에서는 잘못된 경고와 위험 누락 모두 중요하므로 둘을 함께 확인해야 합니다.

**Q. IoU와 NMS는 왜 사용하나요?**  
A. IoU는 두 박스가 얼마나 겹치는지 나타내는 비율입니다. NMS는 같은 물체에 여러 박스가 생겼을 때 보통 점수가 높은 후보를 남겨 중복을 줄입니다. 너무 강하게 적용하면 가까운 두 물체가 하나로 합쳐질 수 있습니다.

**Q. 선풍기는 기본 YOLO 모델이 인식하나요?**  
A. 현재 기본 모델의 80개 클래스에는 선풍기가 없습니다. 선택형 Grounding DINO의 선풍기 질의로 후보를 추가 확인합니다. 추가 모델이 꺼져 있거나 실패하면 그 확인을 할 수 없습니다.

**Q. 책상과 테이블을 어떻게 구분하나요?**  
A. 기본 모델의 테이블 후보와 선택형 모델의 책상·테이블 질의를 사용합니다. 충분히 겹친 테이블·책상 후보에는 책상으로 정리하는 규칙이 있고, 다른 분류 충돌은 확인 필요로 표시합니다. 시각적으로 비슷하면 오분류될 수 있습니다.

**Q. 전선 탐지가 어려운 이유는 무엇인가요?**  
A. 전선은 가늘고 길며 가려지기 쉽고 바닥 무늬·그림자와 비슷할 수 있습니다. 전체 사진 축소 시 픽셀 수가 줄어듭니다. 앱은 하단 영역을 나눠 추가 분석하지만 모든 배치와 조명을 보장하지 않습니다.

**Q. 사진을 나눠 분석하면 항상 좋은가요?**  
A. 작은 대상을 상대적으로 크게 볼 수 있지만 주변 문맥을 잃거나 경계에 걸친 대상이 잘릴 수 있고, 추론 시간도 늘어납니다. 따라서 잘라낸 결과의 좌표를 원본으로 복원하고 겹치는 후보를 정리합니다.

**Q. 위험한 모서리만 정확히 박스로 표시하나요?**  
A. 아닙니다. 현재 박스는 탐지된 가구 후보의 영역이며, 그 가구의 노출 모서리와 동선을 실제로 확인하라는 안내입니다. 개별 모서리 위치나 날카로운 정도를 분할·측정하는 모델은 아닙니다.

**Q. 미끄럼 위험은 무엇을 보고 알 수 있나요?**  
A. 추가 모델이 물기 또는 러그·매트로 보이는 후보를 찾으면 사용자가 젖었는지, 매트가 밀리는지 확인하도록 안내합니다. 사진만으로 바닥의 마찰 계수를 측정하지 않습니다.

**Q. 낙하 위험은 물건의 실제 높이를 측정한 건가요?**  
A. 아닙니다. 사진 위쪽에 보이는 일부 물건을 확인 후보로 삼습니다. 카메라 각도 때문에 사진상 위쪽과 실제 높이는 다를 수 있으므로 가구 가장자리와 안정성을 현장에서 확인해야 합니다.

**Q. 모델이 틀리면 점수도 틀릴 수 있나요?**  
A. 그렇습니다. 점수는 탐지된 확인 항목을 바탕으로 계산하기 때문에 오탐과 누락의 영향을 받습니다. 따라서 점수가 높아도 미탐지 위험이 없다는 뜻은 아닙니다.

**Q. AI가 위험도와 권고 문장을 직접 생성하나요?**  
A. 현재는 아닙니다. 모델은 객체 후보를 반환하고 앱의 사전 정의 규칙이 위험 등급과 권고 문장을 만듭니다. 종합 피드백도 이 항목의 개수와 권고를 정리합니다.

**Q. 종류 확인 필요 항목을 왜 점수에서 제외하나요?**  
A. 모델이 같은 위치의 물체를 다르게 해석했을 때 특정 물체의 위험도를 확정해 점수에 반영하면 오해를 줄 수 있기 때문입니다. 다만 점수에서 제외되더라도 현장 확인은 필요합니다.

**Q. 기기에서 분석하는데 앱 크기가 작은 이유는 무엇인가요?**  
A. 추론 기능은 앱에 포함하지만 모델 가중치는 첫 사용 시 별도로 내려받는 구조입니다. 모델이 설치되면 기기 저장 공간을 사용합니다. 기본 및 추가 모델 다운로드 용량도 고려해야 합니다.

**Q. 모델 다운로드가 바뀌거나 변조되면 어떻게 하나요?**  
A. 앱은 지정된 HTTPS 경로에서 파일을 받고 미리 정한 SHA-256 해시와 일치하는지 확인합니다. 불일치하면 모델을 사용하지 않습니다. 이는 파일 무결성 확인이며 모든 보안 문제를 해결한다는 뜻은 아닙니다.

**Q. 병렬 처리면 어떤 기기에서나 분석이 빨라지나요?**  
A. 아닙니다. 현재 전체 RAM·사용 가능한 메모리·CPU 수 조건을 통과한 경우에만 병렬 처리를 시도합니다. 부하와 발열에 따라 오히려 느려질 수도 있어 동일 기기 실측이 필요합니다.

**Q. 1차 결과가 최종 결과와 다른 이유는 무엇인가요?**  
A. 기본 모델을 먼저 보여준 다음 선택형 모델의 후보를 합치기 때문입니다. 추가 후보가 발견되거나 분류 충돌이 생기면 최종 박스와 점수가 달라질 수 있습니다.

**Q. 정확도 향상을 검증할 사진은 어떻게 구성해야 하나요?**  
A. 밝기, 가림, 거리, 가구 종류, 전선 배경과 카메라 각도가 다양한 사진을 수집하고 물체별 정답 박스와 종류를 표시해야 합니다. 학습·조정용과 최종 평가용 사진을 분리하고 클래스별 오탐·누락을 살펴야 합니다.

**Q. 데이터가 부족한 경우 무엇을 개선할 수 있나요?**  
A. 실제 촬영에서 실패한 전선·모서리·가구 사례를 동의하에 수집해 라벨링하고, 클래스별 오류를 분석할 수 있습니다. 전용 모델 학습이나 교체도 검토할 수 있지만 새 데이터로 개선을 검증해야 합니다.

### 홈캠·보안·운영에 관한 질문

**Q. WebRTC는 영상 파일을 만들어 전송하나요?**  
A. 홈캠의 실시간 시청은 WebRTC 영상 스트림을 사용합니다. 수동 녹화는 모니터링 기기에서 별도로 영상 파일을 생성하는 기능입니다.

**Q. WebRTC를 쓴다면 왜 Tailscale도 필요한가요?**  
A. WebRTC는 영상 연결과 전송에 사용하고, Tailscale은 기기 간 사설 네트워크 경로와 접근 범위를 제공합니다. 현재 앱은 영상 후보를 Tailnet 경로로 제한합니다.

**Q. Tailscale이 없는 일반 인터넷에서도 연결되나요?**  
A. 현재 제공되는 독립 홈캠 흐름은 두 기기의 Tailnet 연결을 전제로 합니다. 별도 인터넷 연결만으로 동작한다고 설명하면 안 됩니다.

**Q. 같은 계정이면 QR 없이 누구나 볼 수 있나요?**  
A. 앱에서는 기기 등록 절차도 사용합니다. 다만 같은 Tailnet에 접근 가능한 기기와 계정 권한, QR·등록 정보 관리가 모두 보안에 영향을 줍니다. QR을 공개하거나 타인에게 공유하면 안 됩니다.

**Q. QR은 영상을 담고 있나요?**  
A. 아닙니다. 촬영 기기를 등록하고 연결하기 위한 정보를 전달합니다. 영상은 등록 이후 별도의 WebRTC 연결로 전송됩니다.

**Q. PC를 끄면 홈캠도 멈추나요?**  
A. 휴대폰 간 독립 홈캠은 PC 서버를 필요로 하지 않습니다. 다만 두 휴대폰의 인터넷·Tailscale 연결과 촬영 기기 앱 실행은 계속 필요합니다.

**Q. 서버가 전혀 필요 없다는 표현이 정확한가요?**  
A. 이 프로젝트의 별도 PC 또는 자체 영상 중계 서버 없이 동작한다는 뜻으로 설명해야 합니다. Tailscale 서비스와 네트워크 인프라, 모델 다운로드 호스팅은 외부 서비스에 의존합니다.

**Q. 인터넷이 끊겨도 사진 점검과 홈캠이 가능한가요?**  
A. 설치된 모델을 이용한 사진 추론은 오프라인에서 가능합니다. 서로 다른 네트워크의 홈캠 연결은 인터넷과 Tailnet 연결이 필요합니다. 다운로드하지 않은 모델은 먼저 받아야 합니다.

**Q. 사람 위치 박스는 얼굴 인식인가요?**  
A. 아닙니다. ML Kit 자세 인식을 이용한 최대 한 명의 위치 표시이며, 개인을 식별하거나 얼굴을 인식하는 기능이 아닙니다.

**Q. 낙상 의심 시 보호자에게 자동으로 신고하나요?**  
A. 아닙니다. 사용자가 켠 실험 기능이 촬영 기기에서 자세 변화를 바탕으로 전후 영상을 저장하려고 시도합니다. 자동 신고·긴급 출동·푸시 알림은 제공하지 않습니다.

**Q. 녹화 영상은 클라우드에 저장되나요?**  
A. 현재 안내된 수동 녹화는 모니터링 기기 내부에 저장하고 Android 10 이상에서 갤러리 복사를 시도합니다. 실험적 낙상 의심 기록은 촬영 기기 안에 남습니다. 앱 원본과 갤러리 복사본은 별도로 관리해야 합니다.

**Q. 휴대폰 화면을 꺼도 촬영하나요?**  
A. 현재는 아닙니다. 촬영 기기는 앱과 화면을 켠 상태를 전제로 하며 잠금·백그라운드 촬영을 지원하지 않습니다.

**Q. Expo Go가 아니라 별도 APK가 필요한 이유는 무엇인가요?**  
A. 앱이 사용하는 WebRTC, ONNX 및 직접 구현한 Android 네이티브 모듈이 Expo Go 기본 앱에 포함되지 않기 때문입니다. 이를 포함한 자체 빌드가 필요합니다.

**Q. 상용화 전에 가장 먼저 보완할 부분은 무엇인가요?**  
A. 대표 환경에서의 클래스별 정확도와 지연 측정, 기기별 홈캠·영상 저장 검수, 계정과 Tailnet 접근 관리, 라이브러리 보안 업데이트, 모델·의존성 라이선스 검토가 필요합니다. 응급 용도로 주장하려면 그에 맞는 별도 검증이 필요합니다.

## 7. 현재 한계와 향후 검증

- 전선·플러그, 작은 물체, 가구 모서리 및 바닥 후보는 놓치거나 잘못 탐지할 수 있습니다. 대표 사진 데이터셋을 이용한 클래스별 측정이 필요합니다.
- 사진 한 장으로 가구의 실제 깊이·높이·재질, 바닥 마찰이나 전기설비 상태를 확정할 수 없습니다.
- 사람 위치 표시와 실험적 낙상 의심 기록은 가림·조명·카메라 각도에 영향을 받으며 응급 감시를 대체하지 않습니다.
- 홈캠은 촬영 기기의 화면과 앱이 켜진 상태를 전제로 합니다. PIP와 저장, 장시간 연결 및 서로 다른 기기에서의 동작은 추가 검수가 필요합니다.
- ONNX Runtime 상향 및 호환성 검증 등 보안 관련 남은 사항은 [보안 안내](../SECURITY.md)를 참고하세요.

발표에서는 위의 **구현된 기능**, **실험 기능**, **추가 검증이 필요한 부분**을 구분해 설명하는 것이 좋습니다.
